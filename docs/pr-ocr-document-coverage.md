# 修复指定文档总结覆盖、多轮检索上下文与 OCR 错误诊断

## 这个 PR 做了什么

用户指定 rag_paper.pdf 总结时，原检索没有文件限制、容易只返回局部技术片段。现在按实际索引的文件名限定来源，以章节标题和多维查询覆盖不同页。短指代追问携带近期用户问题，避免只检索“它”。OCR保留现有自动调用路径并显示实际执行错误。正式评测缺少 key 时拒绝运行。

## 影响的模块

- [ ] app/core（公共方法签名未变）
- [x] app/agent（检索查询上下文、总结预算）
- [x] app/ingestion、app/retrieval（B）
- [x] app/evaluation（缺少key的运行保护，请C审核）
- [x] tests、docs

## 具体行为

指定文件查询不会用其他PDF替代；文件不存在会返回空并告警。来源限定的向量检索失败后使用同范围BM25。总结问题先挑选章节标题所在页，再轮流选取目标、方法、实验和结论查询结果，去重并受top-k约束。总结流程至少请求6条，生成器仍最多接收6条。标题命中项score=0，不用于置信度判断。

多轮规则使用最近两轮用户问题，不使用助手输出作为事实；对未命中的指代仍需A进一步扩展。公共接口无需迁移。

## 验证

## OCR 端到端验收

本机已具备 pdftoppm 与 tesseract 5.5.4，扫描件 HKU_TEC_x_Plug_and_Play.pdf 经 OCR 得到第1页文字、入库1个chunk；真实 HKU DeepSeek-V3.2 问答引用 p.1，日期、时间、地点三条 Claim 均为 supported，无错误。详细命令与结果见 docs/b-ocr-coverage-test-2026-11-19.md。英文扫描页已验收，中文OCR语言包和复杂版式未覆盖。
