# B · 学习型检索与总结验证（2026-11-22）

## 现象和根因

用户说“这个 PDF 都讲了什么”，原流程经常只把两三页片段交给回答模型；即使 PDF 本身有 70 多页实质内容，生成模型看不到其余章节，只能答“证据不足”。此外，可见文件名 `COMP7608B_Lec04.pdf` 的第 1 页内部写的是 `LECTURE 1`，此前只检查内部标题，导致“COMP7608B Lecture 04”误报找不到。

本次修复对应 #78 和 #79。它改的是文档来源选择、代表性页面召回以及模型可见的证据分配。它不会假称 6 条片段等于全文逐页通读。

## 边界与交接

1. UI 当前是共享文档库；如果只说“这篇 PDF”而库中有多份文件，系统要求给出文件名。此次没有新增 UI 的“当前文档”选择器。C 的 #81 可评估默认 Top-K 展示，但 Agent 对学习型问题会自动至少取 6 条，界面可继续显示用户选择的基本 Top-K。
2. 六条代表性片段可做有出处的概览、方法/结果整理和对比，但不能保证覆盖长文每一段。需要完整章节分析时，应按章节或页面继续提问。
3. 模型可能产生没有紧邻引用的错误页码或双方共同点判断错误；Claim Verification 和人工核对仍有必要。对同一主题没有双方证据时，应明确说明，而非编造相同观点。
4. 本次不上传课程 PDF、数据库记录、用户对话、`.env` 或密钥。#49 的正式 50×4×3 实验应在代码与模型冻结后统一重跑；不能沿用本次前的结果。
